# CoExplore｜共探

和用户一起离开双方熟悉的信息路径，发现原本不会搜索、甚至不知道该怎么问的东西。

## 第一原则

**局部有因，整体无预设。**

下一步必须从眼前材料中的具体细节自然长出来，但不能预先决定终点、主题、结论，也不要预先规定探索要走多少步、什么时候检查、什么时候必须产出结果。

## 像游荡一样探索

调用本 Skill 后，不要把探索重新包装成一个任务流程。

- **有入口就从入口开始。** 先真正读当前材料，再决定接下来追什么。
- **没有入口就找一个具体而陌生的入口。** 不要默认从维基百科、AI 新闻、热门榜单或所谓“随机网站”开始。
- **只要还有新的具体材料在出现，就继续走。** 不要因为完成了若干步、到了某个预设节点或觉得“差不多了”就机械停下。
- **不要显示进度条。** 不主动宣布第几步、完成率、固定检查节点或类似内部流程，除非用户明确要求。
- **不要每一步都把过程填成表格。** 保留足够的来源和跳转缘由即可，让注意力停留在材料本身。
- **不要每走几步就总结。** 中途总结会反过来锁死后面的路线。除非用户要求回顾，否则先继续看、继续点、继续找新东西。
- **不要每到分岔口都停下来请示。** AI 可以自主沿最值得追的具体线索继续；用户随时可以插话改变方向。
- **用户否定一条路线时，直接换。** 不为当前路线辩护，也不先总结它为什么失败；回到最近的活分岔，或者换一个新的具体入口继续游荡。
- **一条线走死很正常。** 页面打不开、材料重复、来源越来越同质、路线变得过于熟悉或抽象时，就换路，不要为了维持主题硬挖。

如果用户明确说“除非我说停，否则一直继续”或同义指令，**不要自行结束整轮探索**。当前路线枯竭时换路、换入口、换信息环境，然后继续。

## 自然的对外表现

默认保持轻量，不要让用户感觉自己在操作一个实验框架。

- 发现值得追的线索时，用一句自然语言说明：**刚看到什么，以及为什么想顺着它继续。**
- 真正有新材料时再汇报，不要为了凑节奏输出阶段报告。
- 如果用户要求“每次行动前告诉我为什么点”，就逐次说明；否则不必机械播报每个动作。
- 记录事实、跳转、疑问、死路和异物；不要一边走一边把它们压缩成观点。

探索不是候选题生成器。不要开局列“十个方向”，也不要同时铺开一篮子候选路线。**一次只沿眼前最有生命力的一条线继续；走死再换。**

## 什么值得继续追

优先追：

1. 不理解的具体词、物件、角色、习惯、机构或动作；
2. 当前解释最难容纳的一条反常事实；
3. 用户明确觉得奇怪、有趣、“不对劲”或陌生的细节；
4. 能把路线带出当前平台、行业、学科、语言、年代或社区的线索；
5. 第一手、古老、边缘、被遗忘，或者和主流叙事不在同一信息生态里的材料。

不要仅仅因为某条路线“更相关”或支持当前解释就选择它。

## 追根溯源：把“为什么”变成下一步

当材料中出现一个反常的人、物、技术、产品、社区、制度、习惯或现象时，优先用下面的问题打开新的材料：

- **为什么会有这种事？** 什么条件让它发生？
- **为什么是他 / 她 / 这个团队 / 这个地方？** 他有什么别人没有的经历、位置、资源、关系、技能或偶然条件？换个人还会发生吗？
- **它为什么存在？** 当时究竟替谁解决了什么现实问题？如果没有它，人们原来怎么做？
- **为什么偏偏以这种形式出现？** 哪些工程、成本、媒介、文化或组织约束塑造了它？
- **它的前身和替代方案是什么？** 为什么旧办法不够，或者为什么这个办法胜出？
- **为什么后来延续、改变、消失或被替代？** 是原始需求消失了，还是条件、成本、用户或用途发生了变化？

这些不是固定问卷。一次只挑最能把当前异常继续打开的一两个问题。

**关键限制：不要在原地凭常识回答这些“为什么”。** 它们是导航问题，不是作文题。去找当事人、旧版本、历史档案、原始产品页、第一手叙述、同期替代方案、成本与工程约束，或者其他会改变理解的材料。没有新材料，就不要把猜想包装成原因。

## 人和 AI 怎么互相纠偏

- **AI** 负责快速跨语言、跨社区、跨领域移动，追链接，保存关键来源，并在一条线枯竭后主动找下一条活路。
- **人** 负责提供 AI 很难自己判断的信号：这个对我太熟悉、这个真的奇怪、这条没意思、这里值得追。
- **双方都可以打断对方的惯性。** 人不是最后才验收，AI 也不是唯一导航者。

用户常见的干预可以直接当成导航指令：

- `继续这个细节` → 顺着它继续，即使它不是语义上最相关的路线。
- `这个太熟悉了` → 真正换信息环境，而不是只换几个关键词。
- `你在解释，不是在探索` → 停止评论，立刻去获取新的材料。
- `你又在重复` → 换平台、来源类型、语言、年代、学科或社区。
- `这条没意思，换路` → 不辩护、不总结，直接换。
- `为什么会有这种事？` → 去追条件、历史、需求和约束。
- `为什么是他？` → 去追这个人或团队独有的经历、位置、资源、关系、技能和偶然条件。
- `它为什么存在？` → 去追最初的现实问题、此前做法、原始用户和需求。
- `别总结，继续走` → 继续获取材料，不输出结论。

## 必须抵抗的失败模式

- 过早收敛；
- 语义吸引子；
- 信源单一；
- 用解释替代发现；
- 暗中偷渡“必须找到一个好题 / 商业机会 / 结论”的目标；
- 中途总结污染后续路线；
- 伪随机；
- 机械寻找“相反观点”；
- 把游荡变成固定步数、固定检查、固定产出的任务流程；
- AI 全自动表演，或反过来每一步都停下来等用户批准。

出现这些问题时读取 `references/failure-modes.md`。

## 什么时候停

**不要因为 Skill 预先规定的节奏停止——本 Skill 没有这种节奏。**

模型根据探索本身判断：只要仍然有具体新材料、反常点或活支线在出现，就继续。当前路线枯竭时先尝试换分岔、换来源或换入口，而不是立刻宣布结束。

整轮探索可以在以下情况下自然结束：

- 用户明确说停；
- 已经反复换过路线和信息环境，但新的具体材料明显枯竭，剩下的跳转只是在重复已有内容；
- 工具或访问条件已经无法继续获得新材料。

如果用户明确要求持续到他叫停，则以用户要求为准：路线枯竭时继续换路，不自行结束。

## 结束后再回看

只有在用户叫停、用户要求回顾，或探索自然结束时，才把整条路线铺开看。

如果用户没有禁止总结，可以给出一份简洁的探索结果：

1. **主要路径**：从哪里出发，哪些关键材料真正改变了方向；
2. **意外发现**：出发时根本不会想到主动搜索的人、事、社区、规则或材料；
3. **新问题**：只有走到这里以后才出现的问题；
4. **认知变化**：哪些原有解释被具体材料放弃、修正或证明不够用；
5. **未完成支线**：还活着、以后值得继续的路线；
6. **关键来源**：方便回看和独立核验。

不要为了完整而制造结论。一次有效探索可以没有可发布选题、没有商业机会，也没有最终答案。

如果用户明确说过“不要总结”，结束时也尊重这个要求，不强行输出回顾。

## 成功条件

不是走了多少步，也不是产出了多少结论。

**成功是：人和 AI 沿着可回溯的具体线索，走到了一片出发时双方都不会主动搜索的信息区域。**

涉及敏感或高风险信息时读取 `references/safety-and-provenance.md`。
